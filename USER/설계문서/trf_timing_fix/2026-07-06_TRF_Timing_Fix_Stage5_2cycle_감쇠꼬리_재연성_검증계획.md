# 2026-07-06_TRF_Timing_Fix_Stage5_2cycle_감쇠꼬리_재연성_검증계획

> 본 문서는 확정 계획서가 아니라 아이디어 타당성 검토 단계의 계획서다. 측정 착수 전 파라미터·판정 기준은 예비 측정 결과에 따라 조정될 수 있다.

기준 브랜치: `feature/eu_direct_measurement_10ms`
대상 함수: `IDDD_RunCmd_TRF_Real()` (`USER/L2_Interface/L2_01_IDDD_RunCMD_Interface/IDDD_RunCmd_TRF_Interface.c`)

## 1. 작업 목적

같은 여기(LED ON) 조사를 짧은 간격으로 2회 반복했을 때, 각 LED OFF 이후의 감쇠꼬리(tail)가 서로 얼마나 동일한 파형으로 재연되는지를 정량 확인한다.

1차 tail과 2차 tail을 각자의 LED OFF 시점(t=0)을 기준으로 상대시간 축에 정렬하여 겹쳐 비교한다. 두 tail이 스케일 보정 후 동일 형상이면 Eu 형광감쇠가 여기 조건에 대해 재현성 있는 물리 신호임을 강화하는 근거가 되고, 형상이 크게 다르면 잔류 tail 누적·광표백(photobleaching)·TIA 회복 등 이력(history) 의존성이 존재함을 시사한다.

Stage3(10ms 단발 측정)에서 Eu 직접 조사는 뚜렷한 단조감쇠를, 1.0mm 카세트는 약 2500us에서 미약한 피크를 보였다. Stage5는 그 tail의 반복 재연성을 추가 검증하는 단계다.

## 2. 현재 코드 구조

현재 `IDDD_RunCmd_TRF_Real()`은 TIM3 free-running 카운터(1us tick)를 폴링하며 ADC 단발 변환을 1회 시퀀스로 수행한다.

핵심 파라미터는 다음과 같다.

```c
#define TRF_REAL_SAMPLE_COUNT           200U   // 총 샘플 수
#define TRF_REAL_SAMPLE_INTERVAL_US      50U   // 균일 간격 → 0~9950us (10ms)
#define TRF_REAL_LED_ON_US              200U   // 1차 LED ON 시각
#define TRF_REAL_LED_OFF_US            1200U   // 1차 LED OFF 시각
#define TRF_REAL_DARK_COUNT              10U   // dark 판정용(50us 간격에서는 사실상 미사용)
```

동작 흐름은 다음과 같다.

- ADC를 `Config_Stage1Poll`(단발 변환·SW start·DMA off·79.5 cycle ≈ 1.64us)로 설정한다.
- `TIM3->CNT`를 0으로 리셋한 뒤 `i*50us` 목표 시각까지 `while(TIM3->CNT < dwTarget);`로 바쁜대기한다.
- 목표 도달 시 타임스탬프를 캡처하고, LED ON/OFF 임계를 1회성 플래그(`bLedOnDone`/`bLedOffDone`)로 판정한 뒤 ADC 단발 변환 결과를 `g_TRF_Samples[i]`에 `{tim_us, adc_val}`로 저장한다.
- dark 평균은 `tim_us < LED_ON_US` 샘플만 평균한다.

착수 전 정리가 필요한 두 가지가 있다.

- 함수 헤더 주석이 stale이다(“100 samples at uniform 20us”로 적혀 있으나 실제는 200 samples × 50us). 2-cycle 확장 시 함께 정리한다.
- `TRF_REAL_DARK_COUNT = 10` 고정 방식은 50us 간격에서 dark 구간이 0~450us로 벌어져 LED ON 샘플이 섞인다. Stage3와 동일하게 `tim_us < LED_ON_US` 조건으로 dark를 산출한다.

## 3. 실험 타이밍 후보

| 구간 | 시간(us) | 길이(us) | 비고 |
|------|---------:|--------:|------|
| dark | 0~200 | 200 | baseline |
| 1차 LED ON | 200~1200 | 1000 | 현재와 동일 |
| 1차 LED OFF | 1200 | — | 1차 OFF 기준시점 |
| 1차 tail | 1200~2000 | 800 | OFF 후 0~800us만 관측 |
| 2차 LED ON | 2000~3000 | 1000 | 잔류 tail 위에서 재조사 |
| 2차 LED OFF | 3000 | — | 2차 OFF 기준시점 |
| 2차 tail | 3000~10000 | 7000 | OFF 후 0~7000us 관측 |

## 4. 타이밍 타당성

### 4.1 타당한 점

LED ON 1000us와 OFF 시각은 이미 검증된 값과 동일하여 1차 사이클이 기존 측정과 호환된다. 2차 tail 7000us는 Stage3 direct 측정에서 감쇠가 약 9ms 부근에서 plateau(dark+10)로 수렴한 것과 부합하여 2차 tail 전체 형상을 담기에 충분하다.

### 4.2 타당성 이슈

비대칭 관측창이 첫 번째 이슈다. 1차 tail은 800us, 2차 tail은 7000us이므로 두 tail을 정렬 비교할 수 있는 구간은 공통 상대시간 0~800us뿐이다. Stage3 direct 데이터상 OFF 후 800us(=t 2000us)에서도 raw≈1422로 dark(135) 대비 매우 높아, 1차 tail은 감쇠 초반 급강하 구간만 잘라 보는 셈이다. “초기 tail 형상 재연성”이 목적이면 타당하나, “tail 전체 재연성”은 1차에서 확인할 수 없다.

해상도 비대칭이 두 번째 이슈다. 현재 50us 균일 간격을 유지하면 1차 tail(800us)에는 16점, 2차 tail(7000us)에는 140점이 배정된다. 초기 급강하 구간의 slope 비교에는 50us가 성기므로, 비교 핵심 구간(각 OFF 후 0~800us)의 해상도를 20us 수준으로 맞추는 편이 slope·area 지표 신뢰성에 유리하다.

잔류 tail 위 2차 조사가 세 번째 이슈다. 2000us 시점 1차 tail이 아직 dark로 복귀하지 않았으므로 2차 tail은 “2차 형광감쇠 + 계속 진행 중인 1차 tail”의 중첩이다(7·9절에서 상술).

## 5. 구현 방식 비교

### 5.1 방식 A — 기존 함수 내부에 2번째 임계만 추가

변경이 최소이고 폴링 루프 구조를 재사용한다. 다만 LED 제어 분기가 4개(ON1/OFF1/ON2/OFF2)로 늘고 1회성 플래그가 늘어 가독성이 떨어지며, 단발과 2-cycle 두 모드가 한 함수에 얽혀 회귀 위험이 있다.

### 5.2 방식 B — 타이밍을 파라미터/구조체 테이블로 추상화

N-cycle 일반화가 가능하고 이후 3-cycle 확장이 쉽다. 그러나 현재 1회성 실험 목적 대비 과설계이며 지금 단계에서는 불필요하다.

### 5.3 방식 C — 별도 함수 `IDDD_RunCmd_TRF_Real2Cycle()` 신설(권장)

기존 검증 완료된 단발 경로를 그대로 보존하고, 2-cycle 전용 임계·출력 포맷을 독립적으로 조정한다. 실험 종료 후 제거·유지 판단이 쉽다. LED/ADC/timer 시퀀스 코드가 일부 중복되는 단점이 있으나 공유 헬퍼로 완화할 수 있다.

### 5.4 폴링 vs 타이머 인터럽트

현재 폴링 구조를 유지하는 것이 타당하다. Stage3에서 4ms(20us)와 10ms(50us) 교차검증 결과 동일 시점 ±3% 재현성이 확인되어 폴링 jitter가 tail 비교에 치명적이지 않음이 이미 실증되었다.

## 6. 별도 함수 추가 권장 여부

방식 C를 권장한다. 근거는 다음과 같다.

단발 `IDDD_RunCmd_TRF_Real()`은 10ms 브랜치의 기준 검증 자산이므로 보존 가치가 크다. 2-cycle은 임계 개수, 관측창 비대칭, 출력 포맷(사이클 구분 태그)이 달라 한 함수에 합치면 분기 복잡도가 급증한다. CLI 연결은 현재 `cmdIDDD_TRF_RUN`이 `IDDD_RunCmd_TRF_Real()`을 호출하므로, 신규 커맨드(예: `cmdIDDD_TRF_RUN2`)를 추가해 실험 함수를 분리 호출하면 기존 명령 회귀 없이 병행 실험이 가능하다.

공유 헬퍼(`TRF_SequenceSignal_SetLow`, ADC lock/config, `IDDD_TRF_MeasTimer_Init`)는 그대로 재사용하고 루프·임계·출력만 신규 함수에 둔다.

## 7. tail 비교 지표

각 tail을 해당 LED OFF를 t=0으로 정렬한 뒤 다음 지표를 산출한다.

- peak: OFF 후 최대 raw 및 도달 시각. 1차·2차 peak 시각·크기의 일치도를 본다.
- area(적분): 공통 상대시간 구간(0~800us)의 `Σ(raw − baseline)`. 총 방출량을 비교하며 관측창이 다르므로 반드시 동일 상대구간에서 계산한다.
- slope: 초기 감쇠 구간의 로그 기울기(`ln(raw − baseline)` 선형회귀) 또는 특정 두 시점 간 감쇠율. 감쇠 시정수를 비교한다.
- 2차÷1차 비(ratio): 동일 상대시간에서의 raw 비. 1.0에 가까울수록 재연성이 양호하다. peak비·area비를 함께 본다.
- baseline: 각 tail 직전 dark. 특히 2차 tail은 잔류 1차 tail이 baseline을 들어올리므로, 단순 dark(135)가 아니라 잔류 1차 tail을 외삽한 값을 baseline으로 빼야 순수 2차 성분이 나온다(9절과 직결).

권장 우선순위는 ratio(재연성 직접 지표) → slope(시정수 동일성) → area(총량) → peak(정렬 확인용)이며, baseline 처리는 모든 지표의 전제다.

## 8. 판정 기준

Stage3 폴링 재현성이 ±3%였던 점을 기준선으로, 잠정 판정 기준을 다음과 같이 제안한다(측정 후 조정 전제).

- 재연성 양호: 공통 구간(0~800us) 상대시간별 2차÷1차 ratio가 0.9~1.1 이내로 평탄하고 slope 차이가 ±10% 이내.
- 부분 재연: ratio가 일정 상수(예: 0.7)로 수렴하지만 형상(slope)은 일치. 광표백·누적에 의한 스케일 감소이나 감쇠 물리는 동일.
- 재연성 불량: ratio가 상대시간에 따라 단조 변화하거나 slope 차이가 큼. 이력 의존(잔류 tail 중첩 보정 실패 또는 물리적 열화) 의심.

판정 시 baseline 보정(잔류 tail 외삽 차감)을 적용한 값과 미적용 값을 함께 기록해 보정의 영향도 남긴다.

## 9. 우선 측정 대상

측정 순서는 1.0mm → 0.8mm → 0.6mm를 권장한다.

1.0mm를 먼저 측정한다. Stage3 10ms 단발에서 1.0mm 카세트는 약 2500us에서 peak≈345(dark+210)로 신호가 이미 확인된 기지 조건이므로, 셋업·지표 파이프라인 검증에 적합하다.

이후 0.8mm → 0.6mm로 진행한다. CH3 기존 그래프 기준으로는 틈새가 좁아질수록 광학 전달 효율이 낮아져 신호가 약해지는 방향으로 관찰된다. 따라서 2차 LED ON 시 ADC 포화 위험은 감소하지만, tail 비교 지표의 SNR 저하 가능성이 증가하므로 1.0mm에서 기준 파형을 먼저 확보한 뒤 진행하는 순서가 안전하다.

대조군으로 Stage3와 동일한 empty(빈 상태)를 1회 포함해, 2-cycle에서도 아티팩트가 dark로 유지되는지 재확인한다.

## 10. 리스크

### 10.1 ADC 포화

12-bit(0~4095) 기준, Stage3 direct에서 LED ON 링잉 raw≈1925, 형광 peak≈2563이었다. 2차 LED ON은 잔류 1차 tail(2000us에서 direct≈1422) 위에 중첩되므로 `1925(링잉) + 잔류` 및 오버슈트가 4095에 근접·초과할 수 있다. direct·0.6mm 등 강신호 조건에서 클리핑 위험이 실재한다. LED current를 낮춘 예비 스윕으로 포화 마진을 먼저 확인한다.

### 10.2 잔류 tail 위 2차 조사(중첩)

2차 tail은 2차 형광감쇠와 진행 중인 1차 tail의 합이다. 순수 2차 성분을 얻으려면 1차 tail을 2000us 이후로 외삽(예: 단일 지수 fit)해 차감해야 한다. 외삽 모델 오차가 곧 2차 tail 지표 오차가 되므로, 1차 tail 구간(1200~2000us)에서 fit 품질을 먼저 확보해야 한다. 800us(16점)로는 fit 신뢰도가 낮을 수 있어 이 구간 해상도 상향(20us)을 권장한다.

### 10.3 polling jitter

현재 `while(TIM3->CNT < dwTarget);` + `HAL_ADC_Start/PollForConversion/Stop` 경로는 변환 지연(≈1.64us + HAL 오버헤드)만큼 실제 샘플 시각이 목표보다 뒤처진다. 다만 `tim_us`에 실제 `TIM3->CNT`를 저장하므로 시각은 정확히 기록되고, tail 비교는 절대시각이 아닌 상대시각 정렬이므로 jitter 영향은 제한적이다(Stage3 ±3% 실증이 뒷받침). 리스크는 목표 간격 미세 변동보다 LED ON/OFF 스위칭 시점 지연이 크므로, LED 전환도 실제 `TIM3->CNT`로 타임스탬프를 남겨 두 사이클의 OFF 실측 시각을 정렬 기준으로 삼는다.

## 11. 요약

아이디어는 물리적으로 타당하나 두 tail의 관측창 비대칭과 잔류 tail 중첩이 핵심 난점이다. 별도 함수 신설(방식 C) + 공통 비교구간(OFF 후 0~800us) 해상도 상향(20us) + 잔류 tail 외삽 차감 baseline을 전제로 진행하고, 검증 대상은 1.0mm(기지 신호)부터 시작하는 순서를 권장한다.

## 12. 구현 진행 단계 (확정)

본 절은 1차 구현 착수를 위해 확정한 파라미터와 진행 단계를 정리한다. 4절·11절에서 권장한 20us 해상도, 구간별 가변 샘플링, baseline 외삽 등은 후속 정밀 비교 단계로 이월하고, 1차 구현은 기존 Stage2 설정을 최대한 재사용하는 방향으로 확정한다.

### 12.1 확정 파라미터

샘플 간격은 기존 Stage2와 동일하게 50us 균일 간격을 유지한다. 샘플 수는 200개, 관측 구간은 0~9950us로 진행한다. 20us 균일 샘플링과 구간별 가변 샘플링은 1차 구현에서는 보류하고, 후속 정밀 비교 단계에서 필요 시 검토한다.

버퍼는 기존 `g_TRF_Samples` 구조를 재사용한다. 기존 `IDDD_RunCmd_TRF_Real()`과 신규 함수는 동시에 실행되는 구조가 아니므로 실험 브랜치에서는 기존 버퍼 재사용으로 충분하다. 신규 배열 추가는 필요성이 확인되면 후속 단계에서 검토한다.

`trfrun` 매핑은 이번 실험 브랜치에서 호출 대상을 `IDDD_RunCmd_TRF_Real2Cycle()`로 변경한 상태로 진행한다. 기존 `IDDD_RunCmd_TRF_Real()` 호출 라인은 원복 가능하도록 주석으로 남긴다. 실험 종료 후 결과를 보고 기존 단발 함수로 원복할지, 2-cycle 함수를 유지할지 결정한다.

로그 헤더에는 신규 함수가 아직 1-cycle 복제 상태(1단계)이더라도 `TRF REAL 2-CYCLE SKELETON` 또는 `TRF REAL 2-CYCLE`처럼 구분 가능한 문구를 반드시 출력한다. GUI에서 기존 `trfrun`을 호출했을 때 내부 매핑이 실제로 신규 함수로 바뀌었는지 즉시 확인하기 위함이다.

### 12.2 1단계 — 신규 함수 골격 추가

`IDDD_RunCmd_TRF_Real2Cycle()`을 `IDDD_RunCmd_TRF_Interface.c`에 신설하고 프로토타입을 `IDDD_RunCmd_TRF.h`에 추가한다. 내부는 우선 기존 1번 함수 로직을 복제한 1-cycle 상태로 두어 빌드와 동작만 확보한다. 기존 `IDDD_RunCmd_TRF_Real()`은 손대지 않고 보존한다. 로그 헤더에 `TRF REAL 2-CYCLE SKELETON` 문구를 출력한다. 검증은 빌드 성공과 함수 호출 여부다.

### 12.3 2단계 — trfrun 호출 매핑 교체

`IDDD_RunCommand_App.c`의 `cmdIDDD_TRF_RUN` 케이스에서 호출 대상을 `IDDD_RunCmd_TRF_Real()`에서 `IDDD_RunCmd_TRF_Real2Cycle()`로 변경한다. 기존 호출 라인은 삭제하지 않고 주석으로 남겨 원복이 쉽게 한다. 검증은 GUI에서 `trfrun` 전송 시 로그 헤더에 2-CYCLE 문구가 나오는지 확인하는 것이다(파형은 아직 1-cycle과 동일).

### 12.4 3단계 — 2-cycle 타이밍 파라미터 정의

신규 define으로 `TRF2_LED_ON1_US(200)`, `TRF2_LED_OFF1_US(1200)`, `TRF2_LED_ON2_US(2000)`, `TRF2_LED_OFF2_US(3000)`을 추가한다. 샘플 간격 50us, 샘플 수 200, 관측 0~9950us는 12.1 확정값을 따른다. 검증은 타이밍 합과 버퍼 크기, UART 출력량이 허용 범위인지 확인하는 것이다.

### 12.5 4단계 — LED 4-임계 시퀀스 구현

폴링 루프에 ON1/OFF1/ON2/OFF2 4개 1회성 플래그 분기를 추가한다. 각 LED 전환 시 실제 `TIM3->CNT`를 별도로 기록하여 두 사이클의 OFF 실측 시각을 후처리 정렬 기준으로 남긴다(10.3 대응). 검증은 로그 또는 오실로스코프로 4개 전환 시각을 확인하고, 과거 LED 토글 버그 재발 여부를 집중 점검하는 것이다.

### 12.6 5단계 — 샘플 저장·로그 포맷

`{tim_us, adc_val}` 출력에 OFF1/OFF2 실측 시각을 헤더로 표기하여 후처리 정렬에 사용한다. dark는 `tim_us < TRF2_LED_ON1_US` 샘플만 평균한다. 검증은 empty와 1.0mm 조건에서 raw 파형이 기존 단발 측정과 정합하는지 대조하는 것이다.

### 12.7 6단계 — 실측 (1.0mm 우선)

1.0mm → 0.8mm → 0.6mm 순으로 측정하고 대조군 empty를 1회 포함한다. ADC 포화(특히 2차 ON 구간)와 잔류 tail 중첩 형태를 확인한다.

### 12.8 7단계 — 후처리·판정

로그를 CSV로 옮겨 peak/area/slope/2차÷1차/baseline(잔류 tail 외삽 차감)을 산출하고 8절 판정 기준(ratio 0.9~1.1, slope ±10%)을 적용하여 재연성을 판정한다.

### 12.9 8단계 — 원복 정책

실험 종료 시 2단계 매핑을 기존 `IDDD_RunCmd_TRF_Real()`로 되돌릴지, 신규 2-cycle 함수를 기본값으로 유지할지 결정한다. 실험 코드는 실험 브랜치에만 두고 main 반영 여부는 별도로 판단한다.
